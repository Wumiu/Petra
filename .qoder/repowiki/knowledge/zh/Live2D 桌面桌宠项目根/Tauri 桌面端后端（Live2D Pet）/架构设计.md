模块以 `main.rs` 为入口，仅设置 WebView2 参数（开发时启用 CDP 调试端口、生产禁用代理），随后调用 `pet_lib::run()`；`lib.rs` 是核心：通过 `mod audio/screen/trash` 组织三个原生能力子模块，使用 Tauri State 管理跨线程共享状态（`AudioState`、`PetMotion`、`DragState`），并通过 `#[tauri::command]` 暴露给前端 IPC。

- 进程内多线程架构：`lib.rs` 在 `setup` 阶段启动多个后台循环——16ms 的 pet_mover（按目标点平滑移动窗口）、8ms 的 drag_follower（拖动中直接 GetCursorPos/SetWindowPos 零 IPC 跟随）、16ms 的 clickthrough_watcher（根据光标位置切换 WS_EX_TRANSPARENT）、以及独立音频线程（audio.rs 中的 WASAPI 回环捕获）。所有线程通过 `AppHandle` + `State<T>` 访问窗口句柄与共享状态。
- 平台绑定：screen.rs 通过 raw-window-handle + windows crate 直接调用 Win32 GDI/WindowsAndMessaging API 实现窗口几何与点击穿透控制；trash.rs 调用 Shell SHFileOperationW 将文件移入回收站；audio.rs 使用 WASAPI IMMDeviceEnumerator/IAudioClient 回环模式捕获默认输出设备并 emit `audio:pcm` 事件。
- 配置与构建：`tauri.conf.json` 定义无边框透明置顶主窗口（300x300）、CSP 关闭、bundle 图标集；`build.rs` 委托 `tauri_build::build()`；`Cargo.toml` 声明多 crate-type（staticlib/cdylib/rlib）以便被宿主或其他 crate 引用。
- 诊断通道：集中式 `log_line` 同时写入 stdout 与 app_data/logs/pet.log，并提供 `debug_mark` 命令及 JS 探针注入用于 WebView2 加载诊断。
